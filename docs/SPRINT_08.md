## 3、5｜圖文說明書兩張截圖錯放成公告（同一個主因）

**現象**：`docs/圖文說明書_v0.3.2.pdf` 裡「出席行事曆」與「孩子上過的課程」兩頁，
放的都是首頁公告的畫面。

**主因**：產圖用的測試帳號在截圖當下**只有 `teacher` 標籤**（截圖左上角的角色徽章只顯示「老師」）。
`src/router/index.ts` 對這兩條路由都設了 `meta: { roles: ['parent'] }`：

```
attendance   → meta: { roles: ['parent'] }
my-lessons   → meta: { roles: ['parent'] }
```

沒有家長標籤 → 守衛把 `page.goto()` 導回首頁 → 截到的是首頁。
產圖腳本沒有「檢查最後停在哪個網址」的斷言，所以錯誤沒有被擋下來。

**現況**：組長已於 9/5 把測試帳號補上 `parent` 標籤（現為 `teacher`＋`admin`＋`parent`，
且已綁定一位兒童班孩子），路由守衛不再擋。

**要做的事**：

1. 重新產這兩張圖（連同受 #4、#6 影響的詩歌頁與家長版教案頁一起重拍）。
2. 在產圖腳本加一道**落地網址斷言**：`page.goto(path)` 之後若 `location.pathname !== path` 就中止，
   不再默默截到別頁。這是這次真正的治本，不然換個帳號還會再犯一次。

## 4｜有動作／純歌詞按鈕尺寸與版型

**現況（實測 iPhone 14 / 390×844）**：

| 按鈕 | 實體 | 寬 | 高 | 字級 |
| --- | --- | --- | --- | --- |
| 有動作 | `<a class="link-btn dance">` | 86px | **34px** | **14px** |
| 純歌詞 | `<a class="link-btn lyric">` | 86px | **34px** | **14px** |
| 熟悉度 | `<van-button size="small">` | 69px | **44px** | **17px** |

**主因**：`src/style.css` 把 Vant 的按鈕尺寸整組放大過（給長輩看的）：

```css
--van-button-small-height: 44px;  --van-button-small-font-size: 17px;
--van-button-mini-height:  34px;  --van-button-mini-font-size:  14px;
```

而 `SongsView.vue` 的 `.link-btn` 是手寫的 `height: 32px; font-size: 14px`，
註解寫「外觀比照 Vant small plain button」，但實際數字對到的是 **mini**，不是 small。
所以兩者差了一整階。

**建議做法（治本）**：不要再手寫 CSS 對齊，直接改用 Vant 元件本身——

```vue
<van-button size="small" plain tag="a" :href="linkOf(s.dance_url)"
            target="_blank" rel="noopener noreferrer" icon="play-circle-o">有動作</van-button>
```

Vant 4 的 Button 支援 `tag="a"`，語意仍是連結（可長按複製網址、可另開分頁），
尺寸則由 Vant 變數統一控制，日後改字級不會再有一顆對不齊。
`.link-btn` 三段 CSS（含 `.dance` / `.lyric` 配色）可以整組刪掉，顏色改用 Vant 的 `color` 屬性。

**順帶的版型建議**（組長問「或是你幫我重新審視設計版型」）：

現在同一列三顆按鈕是**三種不同顏色的外框**（橘／綠／紫），視覺重量一樣，
但它們的對象其實不同：

- 有動作、純歌詞 → **家長與孩子預習用**，是這張卡片的主要動作
- 熟悉度 → **只有老師看得到的編輯動作**（`canEditFam`），是次要動作

建議把主要動作做成有底色的（實心或淺底），熟悉度降成灰階 plain，
一眼就能分出「這是給我點的」和「這是老師在維護的」。
待組長確認方向後再細調。

## 6｜家長版教案只顯示指定項目 ✅

**需求**：家長版教案只從教案取「敬拜」「信息／主題（兩者任一有就符合）」「背金句」「彈性時間」，
並保留擴充性，之後可再新增要顯示給家長的項目。

**現行邏輯**（`src/lib/parentLesson.ts`）：不看項目名稱，只看**內容有沒有填**——
`isCourseSegment()` 判斷 `content.trim() !== ''`，有內容才顯示。

**實測目前正式資料**（測試帳號的孩子班別，2026 全年）：

| 口徑 | 列數 |
| --- | --- |
| RPC 目前回傳給家長瀏覽器的 | 46 |
| 家長畫面上實際看得到的（有內容） | 13 |
| 符合白名單的（含空內容） | **21** |
| 白名單**且**有內容 | **5** |

全庫 115 個段落的項目名稱分佈（節錄）：

| 項目 | 筆數 | 其中有內容 |
| --- | --- | --- |
| 彈性時間 | 13 | 3 |
| 敬拜 | 12 | 3 |
| 信息 | 10 | 3 |
| 背金句 | 7 | **0** |

**兩個問題已定案**（見文末 Q1、Q2）：

1. **白名單 × 空內容**：「背金句」7 筆**全部沒填內容**。若改成純白名單，家長會看到
   一整排「背金句」但下面是空白；若維持「要有內容」，背金句就永遠不會出現。
   兩種都不理想，需要組長決定（或請老師開始填內容）。
2. **比對方式**：項目名稱是自由文字，實際資料同時存在「信息」「信息 但以理在獅子坑」「信息／主題」。
   用「包含」比對可以三種都吃到，但也會吃到未來任何含「信息」「主題」兩字的項目。

**另外發現一個現有的權限問題**（不在組長清單裡，但這次一起處理較省事）：

`parent_lesson_segments()` RPC 目前把**整份教案**（含「環境整理」「服事分工」「結束禱告」這些
純流程列）全部傳到家長的瀏覽器，只在前端用 `isCourseSegment()` 過濾。
家長開開發者工具就看得到完整流程表。

依 CLAUDE.md「所有權限規則優先寫成 RLS policy；前端的角色判斷只是 UX，不是安全邊界」，
白名單應該做在 **RPC 裡**才是真的邊界。這也影響「擴充性」要怎麼實作（Q2）。

## 7｜教案段落可複製到任一天／空白項目 ✅

**現況**（`src/views/LessonPlanView.vue` 的 `duplicate()`，v9 #5 做的）：
複製只能**原地**產生副本——

```ts
const created = await createLessonSegment({
  class_group_id: activeGroup.value,     // 寫死＝目前班別
  gathering_date: selectedDate.value,    // 寫死＝目前日期
  ...
  sort_order: target.sort_order + 1,     // 插在原段落正下方
})
```

**需求**：像 Excel／Sheet 複製欄位那樣，複製後可以貼到**任一天**的段落或空白項目中。

**技術路徑**：把「複製」與「貼上」拆成兩個動作——

1. 「複製此段落」改為把段落內容放進一個剪貼簿狀態（`localStorage`，跨頁面／跨日期存活，
   重新整理也還在）。
2. 切到目標日期後出現「貼上」入口，寫入時才決定 `gathering_date` 與 `class_group_id`。
3. `review_text`（課後執行）維持不複製——那是當堂實況，沿用現行決定。

**已定案並實作**（見文末 Q3）：不跨班別、一律新增不覆蓋、只做單段。
剪貼簿邏輯在 `src/lib/lessonClipboard.ts`，含壞掉 JSON／舊格式／無痕視窗丟例外的邊際測試。

## 待確認事項｜組長已於 2026-09-05 拍板

### Q1｜家長版教案的空內容怎麼處理？（#6）｜**定案：C**

「背金句」目前 7 筆全部沒填內容。三個選項：

| 選項 | 家長看到 | 代價 |
| --- | --- | --- |
| A. 白名單 ∩ 有內容 | 5 列 | 背金句永遠不出現；比現在的 13 列更少 |
| B. 純白名單，空內容也顯示項目名 | 21 列（16 列空白） | 一整排空白，像沒做完 |
| C. 白名單 ∩ 有內容，另外請老師開始填背金句內容 | 短期 5 列，之後變多 | 要同工配合填寫 |

我的建議是 **C**：程式照 A 做（不顯示空白列），同時在教案頁對這四個項目加一句提示
「這項會顯示給家長，內容請填寫」，讓老師知道填了會被看到。

### Q2｜白名單放在哪裡？「保留擴充性」是哪一種？（#6）｜**定案：B**

| 選項 | 誰能新增項目 | 是不是安全邊界 | 工作量 |
| --- | --- | --- | --- |
| A. 寫在 `src/lib/parentLesson.ts` 常數 | 只有我改程式碼＋重新部署 | ❌ 前端過濾，家長仍拿得到全部 | 小 |
| B. 寫進 RPC 的 SQL 常數 | 只有我改 migration | ✅ 是 | 小 |
| C. 新增一張設定表（比照「兒童服事項目」） | **同工自己在平台上加** | ✅ 是 | 中，要 migration＋維護頁 |

我的建議是 **B 先做、C 之後再說**：先把邊界補起來（這是紅線問題），
新增項目的頻率應該很低（一年可能一兩次），不值得為它做一整個維護頁。
若組長希望同工能自己加，就直接做 C。

### Q3｜複製貼上的三個行為（#7）｜**定案：不跨班別、新增不覆蓋、只做單段**

1. **要不要跨班別？** 兒童班的段落可以貼到幼童班嗎？
   （技術上可以，但要注意：貼過去的老師欄位、教材可能不適用）
2. **貼上是「新增一列」還是「覆蓋選中的空白列」？**
   組長寫「複製到任一天的段落或是空白項目中」，聽起來兩種都要——
   確認是否兩種入口都做（「貼上為新的一段」＋在空白段落的編輯畫面加「從剪貼簿貼入」）。
3. **要不要多選？** 一次複製一段，還是像 Sheet 那樣圈選好幾段一起搬？
   多選的工作量明顯大一階，建議先做單段。
