# 國度領袖兒童部整合平台（APP / Web APP）需求規格書

> 來源：2026-07 上傳之計畫案 PDF（v1 基準），內容整理如下，作為本計畫的需求基準（Requirement Baseline）。
> 2026-07 組長回饋的功能清單已整併於文末「[需求增補 v2](#需求增補-v2組長回饋2026-07)」。

## 國度領袖兒童異象（計畫核心）

> **培育神國小領袖，活出天父美好的計畫。**

引導孩子建立正確的自我形象與身分認同，明白自己是天父的孩子、獨一無二且有美好的品格與任務，
進而產生願意遵守紀律、學習真理、樂意服事的內在動機，成為有影響力的國度領袖。

**核心三要點**

1. **自我形象**：確信天父孩子的身分，是神獨一無二的創造。
2. **品格塑造**：認真學習真理，活像耶穌充滿愛心、信心與智慧。
3. **活出計畫**：操練服事、增強能力，成為國度領袖。

平台上的每個功能都要回到這個異象檢核——**服事經歷卡是孩子自己的成長軌跡（不比較、不排行）、
出席與紀錄是關懷與行政工具（不施壓、不標籤）**，詳見 `docs/DESIGN_PRINCIPLES.md`。

## 專案背景與目標

為簡化兒主行政流程並建立「神國小領袖」文化，希望透過單一整合平台，處理預先出席統計、現場簽到、備課教材/影音/問題討論、服事履歷、敬拜歌單佈達與家長雙向通知。

## 使用者規模與硬體情境

- **使用者規模**：全教會兒童/幼童/幼幼孩子共 47 位、家長約 26 位、老師約 20 位。
- **主要裝置**：95% 以上使用者（家長、現場老師）皆以手機（iOS / Android 瀏覽器）操作。

## 核心功能需求（按模組拆解）

### 1. 出席預計統計與現場簽到（Attendance & Check-in）

- **家長預先統計（代替預約表單）**：
  - 每週固定時間（例如：週三前）開放家長在系統上勾選孩子「本週是否出席」。
  - 自動統計當週預計出席人數，方便行政窗口預備教材與物資。
- **老師現場簽到（代替簽到表單）**：
  - 主日現場由老師/窗口點選名單進行實到簽到。

### 2. 老師備課與教學資源區（Teacher's Hub & Media Center）

- **每週教材與影音（老師專用）**：
  - 後台可上傳/嵌入當週教學影音（如 GOOD TV《天國英雄榜》YouTube 連結或內建播放器）。
  - 附帶「課堂討論問題」與「帶領提示」文字區，方便老師用手機隨時隨地備課。
- **舞蹈動作教學影片庫**：存放簡化後的 2-3 個舞蹈動作示範短片，供帶敬拜老師提前觀看預備。
- **敬拜歌單發布**：後台可上傳 4 首歌曲（歌詞、音檔或 YouTube 純歌詞版連結）。
- **家長每週預習（家長端）**：每週主日結束後，家長端可看到下週敬拜歌曲與影片連結。

### 3. 服事經歷卡（Service History System）

- **服事履歷紀錄**：
  - 紀錄兒童服事細節（例如：2026/08/15 擔任 收奉獻組長 / 敬拜帶領）。
  - 狀態追蹤：受訓中、已通過核定、服事完成。
- **家長端視角**：家長可在系統內看到孩子的「小領袖服事履歷」。

### 4. 家長戰友連結與公告佈告欄（Parent Communication）

- **資訊佈達**：發布每週聚會公告、下週預告、課堂公約宣導。
- **雙向互動機制**：家長可針對公告進行回覆或簽到。

### 5. 權限管理機制

| 角色 | 權限 |
| --- | --- |
| 管理者（核心同工） | 全權存取、發布教材/歌單、維護名單、審核服事資格 |
| 老師端 | 現場簽到點名、檢視每週備課教材（影音+討論問題）、觀看動作教學影片、登錄服事履歷 |
| 家長端 | 填寫預先出席、預習歌單、查看孩子服事卡與接收公告 |

## 給工程師的開發階段建議（Roadmap）

1. **建議型態**：優先採用 **Web APP（RWD 響應式網頁）或 PWA**，免去 App Store / Google Play 上架審核流程，手機瀏覽器開啟加到主畫面即可使用。
2. **開發優先順序（MVP 最小可行性產品）**：
   - **Phase 1（急用/取代表單）**：預先出席統計、現場簽到點名、敬拜歌單/影片發布、家長佈告欄。
   - **Phase 2（文化深化）**：電子服事經歷卡、雙向互動。

## 跨班別擴充（幼童/幼幼班預留）

- **家長端「切換 / 多孩子綁定」介面（UI/UX）**：一位家長（26 位家長之一）可能同時有大娃（兒童班）與二娃（幼幼班），介面上需支援切換查看，或在勾選出席時可一次勾選多個孩子。

## 未來擴充預留（Future Roadmap）

1. **LINE 機器人/通知串接**：預先出席提醒與歌單自動推播。
2. **家庭延伸祭壇（家長端）**：提供主日討論題回饋與打卡。
3. **關懷警訊機制**：連續缺席自動標示，協助窗口 follow-up。
4. **資料庫預留**：建立 User 資料表時，建議預留生日、大孩子階級（培訓中/正式領袖）與家庭關聯 ID。

| 開會決議（班內） | ✅ | ✅ | — | 班別分區的決議紀錄 |

## 三、行政／總務／環境

組長清單中列出此分類但未附功能項目——**待確認**（見「待釐清問題」）。

## 四、核心同工（管理者）

以上功能全部可使用（跨班別、全模組存取），並負責名單維護、服事資格審核、內容發布。

## 個資紅線（設計此區功能前必讀）⚠️

對照 `docs/DESIGN_PRINCIPLES.md` 紅燈規則 #6（個資最小化）、#7（不羞辱、不標籤化）：

1. **通訊錄**：只存服事聯繫必要欄位（家長稱呼、電話或 LINE 擇一即可）；不存住址、身分證等；僅老師與核心同工可見，家長之間互不可見。
2. **當週課後特別狀況紀錄**：
   - 目的是**老師間的關懷交接**（例：今天情緒低落、家中有狀況需代禱），不是行為評語簿。
   - 僅該班老師與核心同工可見；**不對家長端顯示**、更不對其他家長顯示。
   - 欄位設計以「客觀事實＋後續關懷行動」為主，避免累積成孩子的負面標籤。
3. **熟悉指數**：標記對象是「班級 × 詩歌」，不是「孩子 × 詩歌」；不得出現任何個別孩子的能力評比。

## 對 Roadmap 的影響（建議分期）

- **Phase 1（不變，急用取代表單）**：預先報名 → 自動點名表、現場點名、歌單發布、公告佈告欄。
- **Phase 2（老師營運區，v2 主要新增落點）**：班別分區、名單/通訊錄、老師服事排班表、開會決議、教案/PPT 連結、流程運作要點、詩歌熟悉指數。
- **Phase 3（文化深化，原 Phase 2 併入）**：服事報名表 → 服事經歷卡全流程、公告雙向互動、當週課後特別狀況紀錄。

3. 通訊錄需要哪些欄位？誰可以看？（建議：僅老師/核心同工，欄位最小化）

# 需求增補 v3（組長 PRD v1.0＋反饋決議，2026-07-30）

> 來源：組長整理之《兒童主日學親師平台 PRD v1.0》（2026-07-29，將再與師母確認）
> ＋平台負責人反饋裁決。本節記錄**已定案**的決議；教案/課堂紀錄/運作流程/教材庫
> 等待組長更新詳細版後再增補。

## 已定案決議

### 1. 出席頁改為行事曆呈現（家長專屬視角）

- 出席填寫頁以**行事曆**顯示，日期為**可點按**（預留未來開放填寫整月/未來日期）。
- **嚴格家長視角**：出席填寫頁只顯示自己綁定的孩子；老師/同工若無綁定孩子，
  此頁即無孩子可填（點名頁的全班預先報名資訊不受影響，仍供老師點名用）。
- 出席預設值**維持「未定」**（不採 PRD 的預設出席）。
- 現有的「未填提醒」照常顯示。

### 2. 點名依班別差異化＋專心/配合指數

- 幼幼班點名**不含**專心/配合指標（精簡版）。
- 專心/配合**指數（Emoji 量表）家長可見（僅自己孩子）；老師文字備註仍不對家長顯示**
  ——守則張力 a 之裁決。

### 3. 老師標籤班別化（重要架構決議）

- 老師不再是單一標籤，區分為**兒童班老師／幼童班老師／幼幼班老師**。
- 點名、課堂紀錄（教師日誌）等功能**依班別標籤對應顯示與授權**：
  幼幼班老師不能點名兒童班、不能編寫兒童班日誌（RLS 層強制）。
- 實作方式：`roles` 保留 `teacher` 標籤＋新增 `teacher_class_assignments`
  （老師×班別）關聯表；介面顯示為「＊＊班老師」標籤。

### 4. 公告班別化

- 各班老師只能發布/修改**自己班別**的公告，**不允許跨班發公告**；
  同工（admin）可發布/修改全部。
- 公告需新增班別歸屬欄位（全體公告 vs 班別公告）。

### 5. 詩歌模組擴充

- 每首歌需支援**多個影片連結**：目前需要「詩歌」＋「詩歌舞蹈」兩種。
- 可**一次上傳整學期**的歌；以上傳時間排序（越新越上面）。
- 歌單標籤按班別＋週次：「本週＊＊班的詩歌」「下週＊＊班的詩歌」。
- 熟悉度：「歌曲熟悉度」與「動作熟悉度」兩維度，於**日誌流程填寫**、
  於**詩歌頁同步顯示**（班別 × 歌曲；幼幼班老師不需填寫）。

### 6. 其他守則裁決

- 集點卡：OK，維持「不做孩子間點數排名/比較」前提。
- 活動花絮：**僅審核通過的成員可看**；儲存空間**使用率超過 80% 時提醒同工
  將圖片轉移到教會 Google 雲端**（平台留連結）。
- 出席預設值：**維持「未定」**（守則張力 d 定案）。

## 待釐清

1. ~~指數給家長的呈現形式~~ ✅ 已定案（2026-07-30）：**本週指數＋近三週走勢**
   （幼幼班僅顯示出席勾勾；走勢僅近三週、不做累積評比——依 Figma S3）。
2. 教案編寫、課堂紀錄（教師日誌）、運作流程、教材庫：等組長詳細版。

# 需求增補 v4（組長 PRD v2.0＋裁決，2026-07-31）

> 來源：《兒童主日學親師平台 PRD v2.0》（2026-07-31，55 項需求：紅標 31 項九月前、
> 藍標 24 項後續）＋平台負責人裁決。完整分析與產品架構圖見對話紀錄 artifact。

## 已定案裁決（覆蓋 v2/v3 之處以本節為準）

1. **出席預設值：維持「未定」**（不採 PRD 預設出席；守則紅燈 #2）。
2. **專心度/配合度改版**（取代 v3 的單維 emoji 指數）：
   - 兩維數字 **1–5**（下拉預設 5），於點名列即點即存；幼幼班不評。
   - **僅老師與同工可讀，家長不可見**（獨立資料表 `performance_scores`＋RLS；
     v3「指數家長可見」作廢）。表情標籤（moods）維持家長可見不變。
   - 老師端點孩子姓名可調閱**近三個月**出席＋指數走勢＋老師備註。
3. **詩歌熟悉度**：兩維（歌曲/動作）改 **1–5（1＝不熟、5＝熟悉）**，記錄於詩歌曲目上
   （班別 × 歌曲）；老師可於**詩歌頁直接編輯**，也可於課堂紀錄流程覆寫。
4. **歌單呈現維持「班別區分」**，**不採** PRD 的【本週曲目】【新歌專區】【所有歌曲】
   三區版本；依現行共編 Excel 採「期間歌單」（如 2026年7-8月雙月歌單）。
   **幼幼班無詩歌模組**——幼幼班只有點名系統＋老師課後紀錄（2026-07-31 補充裁決）。
5. **點名現場加入**：僅能**從全校名冊挑人**加入當日點名（記為現場加入），
   **不開放老師自由輸入建檔**；名冊沒有的孩子由同工於名單頁建檔。
   核心情境是**升班**（如幼幼班→幼童班）：挑人視窗提供兩種動作——
   「今日加入」（只算當天，跨班參加）與「轉入本班」（正式改孩子班別，
   同工權限，之後每週都在本班名冊）。點名紀錄自帶「點名所屬班別」，
   升班前的歷史紀錄不受影響。

## 執行面裁決（A–D）
