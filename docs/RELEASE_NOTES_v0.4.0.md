## 1｜介面上的「主日」一律改為「聚會日」

聚會在**週六下午**，介面卻寫「主日」，家長會讀成星期日——組長回報實際造成過誤會。

改了 9 處，影響面最大的是 `formatGathering()` 的日期後綴 `（主日）` → `（聚會日）`：
點名、出席、教案、服事、詩歌各頁的日期都走它。

CLAUDE.md 的規則同步更新為「**介面文案一律寫聚會日**」，並註明推翻先前
「可用教會慣用語」的寫法，避免日後又改回去。歷史名稱（舊名「兒童主日學整合平台」）保留。

## 2｜修正：平板上軟體鍵盤遮住底部彈窗的輸入框

老師回報平板編輯「課後執行」時鍵盤會蓋住輸入框，權宜做法是**長按**才看得到。

長按能用不是錯覺——它走的是**文字選取**的捲動路徑，跟一般聚焦不同，剛好命中另一條沒壞的路。

**主因**：底部彈窗是 `position: fixed; bottom: 0`、高度 `85dvh`。軟體鍵盤**不會**縮小版面視窗
（`vh`／`dvh` 與 `window.innerHeight` 都不受鍵盤影響），只縮小**視覺視窗**。
所以彈窗維持原高度貼在版面視窗底部，下半截整個躲到鍵盤後面。
而瀏覽器原生的「把聚焦欄位捲進畫面」是捲**頁面**，彈窗是 fixed 捲不動；
彈窗內部的捲動容器瀏覽器又不會幫忙捲——兩條路都斷了。

**修法**（全站 13 個檔案、28 處底部彈窗，所以修在共用層）：
用 `visualViewport` 算出鍵盤高度寫進 CSS 變數，讓彈窗往上讓開並縮減高度；
再監聽 `focusin`，彈窗內欄位聚焦後主動捲到可視範圍中間。

實測（iPad 直向、模擬鍵盤 340px，鍵盤上緣 y=840）：

| | 彈窗底部 | 最後一個欄位底部 |
| --- | --- | --- |
| 修正前 | 1180 | 950 ← 在鍵盤後方 110px |
| 修正後 | **840** | **772** ← 完全可見 |

## 3｜服事表顯示預排主題

「服事表會有預排好的主題，讓老師在排好服事的同時知道自己當週要帶什麼。」

`service_weeks` 早就有 `topic` 欄位、卡片也已經在渲染「📖 主題」，但用不起來：

1. **被發布鎖住**——老師要等同工按「發布」才看得到，但需要主題的時機正是**報名前**
2. **生命週期不同**——主題學期初一次排完整年，服事每週才安排。綁在一起等於逼同工
   「為了記一個主題先安排一整週服事」。資料佐證：`service_weeks` 只有 4 筆、其中只有 1 筆填了主題

改動：

- 新表 `class_topics`（聚會日 × 班別 × 主題），RLS **讀 `is_staff()`、寫 `is_admin()`**
  → **同工可編輯＋查看、老師只能查看**
- 服事頁每張班別卡多一顆「**主題**」鈕（僅同工）；主題**不論有沒有安排、有沒有發布都顯示**
- 「安排」彈窗移除「主題課程」欄位，避免兩個地方能改同一件事
- migration 把既有 topic 搬進新表；`service_weeks.topic` 保留但停用

依裁決**不做 Google Sheet 匯入**，手動填即可。

## 4｜服事頁顯示各班預計出席人數

老師問「我要怎麼知道 10/3 有哪些小朋友會出席」。

查下來**資料與權限本來就有**——RLS 允許同工讀全部預先出席、`listPlansRange()` 也早就寫好。
缺的只是入口：點名頁寫死只看下一次聚會。而家長其實已經在填未來了（10/3 當時已有 10 人勾出席）。

聚會日卡片加一行「**🙋 預計出席：兒童班 10、幼童班 4、幼幼班 3**」。
只算「出席」（請假與未定都不是「會來」），掛零的班別不列。

> 這個做法只給**人數不給名單**。若老師實際用起來仍需要知道是哪幾位（預備材料、分組），
> 點名頁加日期切換即可補上。

## 開發流程新增規定

CLAUDE.md 新增「**收尾檢查**」三項，每次需求實作完畢後必跑：

1. 版號要不要動（有 migration → 升次版號；純前端 → 升修訂號）
2. 用測試帳號上去實際看一輪
3. 手冊要不要更新（`docs/HANDBOOK.md`＋網頁版 artifact＋圖文說明書）

這一版就是照這個流程收尾的，第 2 項實際抓到一個問題：migration 修 `not null` 時
把 `default auth.uid()` 一起刪掉了，導致從平台寫入也記不到是誰改的（測試全綠但功能不對）。
