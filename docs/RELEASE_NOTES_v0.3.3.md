## 1｜稱呼建議改為「直接填名字」

原本建議填「○○媽媽」「○○老師」，會讓同一個人在老師名單與家長名單出現兩種稱呼造成誤會。

- 註冊頁「稱呼」欄 placeholder → 「請填您的名字」
- 「我的 → ✎ 修改稱呼」說明 → 「這是平台上顯示給其他人看的名字，請直接填您的名字」
- 手冊兩處同步

**不動既有資料**：已經填成「○○媽媽」的成員維持原樣，需要本人到「我的 → 修改稱呼」自行更新，
或由同工在名單頁協助修改。

## 2｜手冊移除「重要標籤已改為分類」

那句是給看過舊版的人的過渡說明，新讀者不需要。只留「要強調的公告請用置頂（📌）」。

## 3、5｜圖文說明書兩張截圖修正

「出席行事曆」與「孩子上過的課程」兩頁原本放的是首頁公告的畫面。

主因：產圖帳號當時只有 `teacher` 標籤，而這兩條路由都設了 `meta: { roles: ['parent'] }`，
守衛把它導回首頁，而產圖腳本沒有檢查「最後停在哪一頁」，所以錯誤沒被擋下來。

已重新產圖，並在腳本加上**落地網址斷言**——導頁就中止、不產出任何圖，避免同樣的錯再犯。

## 4｜詩歌頁按鈕尺寸與版型

「有動作」「純歌詞」比旁邊的「熟悉度」矮一截、字也小一號：

| | 改前 | 改後 |
| --- | --- | --- |
| 有動作 / 純歌詞 | 86×**34**px，字 **14**px | 93×**44**px，字 **17**px |
| 熟悉度 | 69×44px，字 17px | 不變 |

原因：`.link-btn` 是手寫的 `32px/14px`，註解寫「比照 Vant small」，但那個數字其實對到的是
Vant **mini**——本站在 `style.css` 把 small 放大成 44px/17px 給長輩看，所以整整差一階。

改用 `van-button` 本體（`tag="a"` 保留連結語意，仍可長按複製網址、另開分頁），
尺寸交給 Vant 變數統一控制，日後調字級不會再有一顆跑掉。

**版型也一併調整**：三顆按鈕原本是三種顏色的外框、視覺重量一樣，但對象不同——

- 有動作、純歌詞＝**家長與孩子預習用**的主要動作 → 改為淺底色（橘／綠）
- 看歌詞、熟悉度（只有老師看得到）＝次要動作 → 灰階 plain

淺底＋深字沿用公告分類標籤的既有語彙，也避開實心橘配白字對比不足的問題。

## 6｜家長版教案只顯示指定項目

家長端「孩子上過的課程」現在只顯示 **敬拜／信息（或主題）／背金句／彈性時間**，
且**要有填內容**才會出現。

- 「信息」與「主題」是同一件事的兩種叫法，**任一符合就算**
- 用「包含」比對而非完全相等——`item` 是老師手打的自由文字，正式資料同時存在
  「信息」「信息 但以理在獅子坑」「信息／主題」三種寫法
- **沒填內容不顯示**：空白列對家長沒有意義（實測「背金句」7 筆全部空白），
  改由教案頁提醒老師

**教案頁新增給老師的提示**：這四類段落的卡片上會標「**家長看得到**」，
內容沒填時顯示「（內容未填寫——這項會顯示給家長，沒填就整段不會出現）」；
編輯彈窗選到這類項目時也會出現說明。

**順帶修掉一個權限問題**：`parent_lesson_segments()` 原本把**整份教案**
（含「環境整理」「服事分工」這些純流程列）都送到家長的瀏覽器，只在前端過濾——
家長開開發者工具就看得到完整流程表。白名單已下放到 RPC，依 CLAUDE.md
「前端的角色判斷只是 UX，不是安全邊界」。

**要新增顯示給家長的項目**：改 migration 裡的 `array[...]` 與
`src/lib/parentLesson.ts` 的 `PARENT_VISIBLE_ITEMS`，兩邊有對照測試，改一邊沒改另一邊會紅。

## 7｜教案段落可複製到任一天

原本「複製此段落」只能原地複製（日期與班別寫死成當下的）。
改成像 Sheet 複製欄位那樣的兩段式：

1. 編輯段落 →「**複製此段落（可貼到其他日期）**」
2. 切到任一天 → 上方出現 📋 提示列 →「**貼到這天**」

- **不跨班別**：兒童班的段落只能貼回兒童班（貼錯班的老師欄位與教材通常不適用）
- **新增不覆蓋**：一律插在該天最後面，不會蓋掉任何既有段落
- **一次一段**：不做多選，避免一次貼進一堆重複段落
- 課後執行（`review_text`）不複製——那是當堂實況
- 剪貼簿存在 `localStorage`，切日期、重新整理都還在
