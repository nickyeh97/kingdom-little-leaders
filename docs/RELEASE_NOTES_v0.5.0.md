# v0.5.0 更動內容（2026-10-01）

需求增補 v19（組長一項）。**升次版號（`0.4.3` → `0.5.0`）**：有 migration 動到資料庫結構（`lesson_segments` 加欄位、RPC 改寫）。

## ⚠️ 部署前要做的事

在 Supabase SQL Editor 執行 `supabase/migrations/2026-10-01_parent_visible_toggle.sql`。

這支 migration **只該執行一次**：它會把符合舊白名單的既有段落回填成「顯示給家長＝開」。
重跑的話，老師後來手動關掉的段落會被再度打開。

回填時會暫時關掉 `trg_touch_lesson_segment`：這個觸發器會把 `updated_by` 改成 `auth.uid()`，在 SQL Editor 裡沒有 JWT 會變 NULL 撞 not null（第一版就是這樣失敗的）；順便讓既有段落的「最後修改者／時間」維持原樣，不被系統回填蓋掉。

部署順序：**先跑 migration，再部署前端**。前端寫入時會帶 `parent_visible` 欄位，欄位不存在會寫入失敗；
反過來（先跑 migration、舊前端還在）沒問題——舊前端不帶這個欄位，資料庫用預設值 `false`，
但這段期間老師新增的段落家長會看不到，直到有人開啟開關。所以兩步之間不要隔太久。

## 教案段落要不要給家長看，由老師自己決定

v14 #6 的做法是「項目名稱符合白名單（敬拜／信息／主題／背金句／彈性時間）就給家長看」，清單寫死在 RPC。
組長要的是每個段落後面一顆開關，老師自行決定。

### 改動

- `lesson_segments` 加 `parent_visible boolean not null default false`
- migration 回填：符合舊白名單的既有段落設 `true` → **切換當下家長看到的內容一筆都不變**
- RPC `parent_lesson_segments` 改看 `s.parent_visible`，不再比對名稱；「有填內容才顯示」維持不變
  （組長定案：開關打開但內容沒填，家長端還是不顯示，教案頁會提醒老師填）
- 教案編輯視窗加「👨‍👩‍👧 顯示給家長」開關；開著時顯示提醒文字
  - 新段落的預設值跟著項目名稱走（舊白名單降級為預設值）；老師一旦自己撥過開關就不再自動改
  - 以標準流程建立的段落同樣依項目名稱給預設值
  - 複製／貼上段落連開關一起複製；舊剪貼簿格式沒有這個欄位時依項目名稱補預設
- 時間軸卡片的「家長看得到」標籤與「沒填會提醒」改看欄位
- 匯出 CSV 多一欄「家長可見」
- 前端 `isCourseSegment()` 不再按項目名稱過濾——否則老師替自訂項目（如「破冰」）開了開關也會被前端擋掉

安全邊界仍在資料庫：家長端只走 RPC，拿不到 `parent_visible = false` 的列；前端開關只是老師的操作介面。

### 驗證

`npm test` 29 檔 260 項全綠（parentLesson／lessonClipboard 測試已改成新語意）、`vue-tsc`、`npm run build` 通過。

⚠️ **這一版沒有跑測試帳號實機走一輪**：開發容器換新後 `.env.local` 不在了。
migration 跑完後請用測試帳號確認三件事：
1. 家長端「孩子上過的課程」內容與升級前一致（回填正確）
2. 教案頁某段落關掉開關 → 家長端那段消失；打開 → 回來
3. 新增一段「破冰」、打開開關並填內容 → 家長端看得到
