## 1｜各班別小朋友的顏色區分

**需求**：兒童班＝太陽色、幼童班＝天藍色、幼幼班＝嫩綠色。

- 新增 `src/lib/classColor.ts`：以**班名**對應顏色（比照 `performance.ts` 既有的依班名判斷慣例），
  未知班別回傳中性色，不讓新班別壞掉。
- 顏色進 `src/style.css` 成為 CSS 變數（`--kll-class-kid` / `--kll-class-tod` / `--kll-class-baby`
  ＋各自的 soft 底色），標籤用「soft 底＋深色字」確保對比度足夠（太陽色配白字會看不清楚）。
- 套用位置（2026-08-29 定案：**全部**）——孩子旁的班別標籤、班別頁籤、出席紀錄的班別小標與統計列：
  點名、出席、出席紀錄、課堂紀錄、名單、服事、教案、聚會流程、教材、公告、詩歌。
- 邊際：家長端只看得到自己孩子，顏色僅作辨識用途，**不得**衍生成班級之間的比較或排序
  （`docs/DESIGN_PRINCIPLES.md` 紅燈規則 #1）。

## 2｜聚會流程支援 Google Sheet 匯入

**需求**：開放用 Google Sheet 直接匯入填寫；欄位對不起來要提示同工。

- **不走 Google API**（CLAUDE.md 決議 3：教會雲端 Service Account 授權未到位）。
  做法：同工在 Google Sheet 選取範圍 → 複製 → 貼進平台的「貼上匯入」框（TSV），
  或上傳 CSV；解析後先出**預覽表**，確認才寫入。
- 欄位對映（第一列為表頭，順序不拘）：`項目/標題`、`必要性`（必做/選做）、`建議分鐘`、`內容`。
- 錯誤提示要具體到列與欄：缺少必要欄位（列出缺哪一欄）、必要性不是必做/選做、
  分鐘不是數字、整份沒有資料列——一次列出前 N 筆問題，不要只說「格式錯誤」。
- 匯入模式（2026-08-29 定案）：預覽畫面上由同工選 **「附加在現有項目之後」或「整份取代」**
  （取代需二次確認），不做「智慧合併」。

## 3｜聚會流程新增時可決定插入位置與建議時間

**需求**：像表單「向下插入一列」，並可填該段的建議時間。

- 新增彈窗加「插入位置」選擇（＝在哪一項之後；預設最後）與「建議分鐘」欄位。
- 插入後重排 `sort_order`（沿用教案頁既有的重排寫法）。
- **需要 migration**：`class_docs` 增 `minutes int null`。目前建議時間是塞在 `extra` 文字裡
  （如「必做・約5分鐘」），無法可靠讀取；改為獨立欄位，舊資料以既有文字解析回填一次。

## 4｜教案標準流程改為依聚會流程

**需求**：聚會流程新增段落後，教案範本要跟著變（現在固定 11 段）。

- 現況：教案「⚡以標準流程建立」讀的是程式碼常數 `LESSON_TEMPLATE`（`src/lib/lesson.ts`，
  11 段共 88 分鐘），與聚會流程頁的資料（`class_docs`）完全無關，所以流程頁增減不會影響教案。
- 改法：一鍵建立時先讀**該班**的聚會流程（`kind='flow'`，依 `sort_order`），
  以 `title` 為段落項目、`minutes`（#3 新增）為時長；**該班沒有流程資料才退回內建 11 段**。
- 邊際：流程項目沒填分鐘 → 該段時長留空（後續段落時間連動遇空值本來就會停止推算）；
  幼幼班無教案模組，不受影響。按鈕上的「（N 段）」要跟著實際筆數變動。

## 5｜教案「複製此段落」

**需求**：老師常要寫內容、老師、時間、教材相同或相近的段落。

- 段落編輯彈窗加「複製此段落」：複製 `item/content/teacher_text/materials_text/time_text`，
  插入在原段落之後、`sort_order` 重排，`review_text`（課後執行）不複製。
- 複製後直接開啟新段落的編輯彈窗，讓老師接著改。

## 6｜詩歌「有動作」「純歌詞」有時不跳轉 YouTube

**現況**：兩顆按鈕都是 `openUrl()` → `window.open(url, '_blank')`（`SongsView.vue:120`）。

**影片實證（2026-08-31 組長錄影，桌機 Chrome／永活盼望的「純歌詞」）**：

| 觀察 | 結果 |
| --- | --- |
| 點擊是否觸發 | ✅ 按鈕呈按下狀態，點了多次 |
| 是否開新分頁 | ❌ 分頁列數量前後完全沒變 |
| Chrome 是否顯示「快顯已封鎖」圖示 | ❌ 網址列右側無任何變化 |
| 連結資料是否正常 | ✅ `https://www.youtube.com/watch?v=KVDpKlkwDVc`，無前後空白；同一網址貼到新分頁可正常開啟 |

→ **原先「網址少 `https://`」的推測不成立**：資料正常、點擊有觸發，卻連分頁都沒產生。

**組長回報的第二組線索（2026-08-31）**：無痕視窗點同一顆按鈕**會跳轉**；手機遇到時**重整就恢復**。

→ 排除「擴充功能封鎖快顯」（手機沒有擴充功能）。三個現象的共同點是：
**出問題的不是程式，是那個「開很久」的頁面實例**——無痕＝全新實例、重整＝重建實例，所以都正常。

**為什麼頁面會卡住（查證結果）**：本專案的 PWA 更新處理是空的。

- `dist/registerSW.js` 只有 `navigator.serviceWorker.register('/sw.js')`——**註冊完就不再檢查更新**，
  頁面開著多久都不會知道有新版本，也沒有任何「有新版本，請重新載入」的提示。
- 產生的 `sw.js` 走 `skipWaiting` + `clientsClaim`（`registerType: 'autoUpdate'`）：新版一部署，
  新的 Service Worker 會**立刻接管**並改用新的 precache 清單。
- 結果是「舊頁面 × 新資產」的混版狀態：**記憶體裡跑的是舊版 JS，但快取裡的檔案已被換成新版**。
  舊版的延遲載入分頁（`SongsView-xxxx.js` 這類帶雜湊的檔名）在新版已不存在，
  於是「點了沒反應、重整就好」——手機把平台加到主畫面、分頁長期不關的人最容易踩到。

**修法（兩層）**：

1. **不讓這個動作依賴 JS**：兩顆按鈕改為真正的連結 `<a href target="_blank" rel="noopener">`
   （外觀維持按鈕）。即使頁面 JS 進入異常狀態，點連結仍會導覽；順帶支援長按/右鍵開新分頁，
   iOS Safari 對 `window.open` 的限制也一併避開。
2. **治本：補上 PWA 更新機制**（見追加項目 11），讓使用者不會長期停留在舊版程式。
3. 連結正規化仍保留（補 `https://`、去空白與全形字元），防其他歌曲網址格式不良。

## 7｜發布公告內容的輸入對齊

**需求（2026-08-29 澄清）**：輸入框裡的文字要**靠左對齊**。

- 查證：`style.css` 沒有任何對齊覆寫，Vant `van-field` 預設就是靠左，所以問題不在文字對齊，
  而在**版面**——「標題」「內容」標籤佔住左半邊，輸入區被擠到右側，多行公告看起來像從中間開始。
- 修法：公告彈窗的標題/內容改為**標籤在上、輸入框整寬**（Vant `label-align="top"` 或移除 inline label
  改用欄位小標），文字自然從左緣開始；其餘表單維持現狀，避免無謂的全站改版。
- 實作後於 PR 預覽站確認實際觀感再定案。

## 8｜切換分頁時回到頁面頂端

**需求**：手機在下方切換分頁後，會停在原本的捲動位置、看不到上方內容。

- 在 `src/router/index.ts` 加 `scrollBehavior`：一律回到頂端（`savedPosition` 也不還原，
  因為分頁切換是「換頁」不是「返回」）。
- 邊際：彈窗開啟中的捲動不受影響；`ImagePreview` 等覆蓋層自行處理。

## 11｜追加：PWA 版本更新機制（治本，2026-08-31 由 #6 追出）

**問題**：頁面開著就永遠停在舊版程式，只能靠使用者自己「重整」才會好——這不只影響詩歌連結，
任何改版後的新功能、修好的 bug，長期開著的使用者都拿不到。

- 改法：`main.ts` 改用 `virtual:pwa-register` 的 `registerSW`，並：
  - 每隔一段時間（例如 60 分鐘）與「頁面重新取得焦點」時呼叫 `updateServiceWorker` 檢查更新；
  - 有新版本時顯示明確提示（「平台已更新，點此重新載入」），由使用者按下才重載，
    避免在填寫表單時被強制刷新（出席、教案、課堂紀錄都有未存草稿的風險）。
- 加上**延遲載入失敗的保護**：`router.onError` 遇到動態匯入（chunk）載入失敗時，
  自動重新載入一次頁面（以 sessionStorage 記錄，避免無限重載迴圈）。
- 加上全域錯誤處理：`app.config.errorHandler` 與 `window.onerror` 出現未預期錯誤時，
  顯示「頁面發生問題，請下拉重新整理」的提示，把「靜默卡住」變成看得見、可自救的狀態。
- 驗證方式：本機建置 → 部署預覽 → 開著頁面再部署一次新版 → 確認會跳出更新提示而不是靜默卡住。
